# お手本の点検結果と修正指示(2026-11-17)

全 58 本の「お手本」(`variants.good`)を、セオリーどおりの動きになっているか・画面の座標が文章の主張と合っているかの 2 点で点検した。
きっかけは「パスコースに顔を出そう(サイドで 2 番が追われた時)」で、7 番の移動先が 2 番と 6 番の直線上にあり、三角形ができず、自分でパスコースを消している指摘(利用者、2026-11-16)。

この文書は **別セッション・別エージェントが修正作業を行うための指示書**。1 件ずつ独立に直せるよう、修正案は座標まで書いてある。

## 1. 進め方(修正を行うエージェントへ)

- 作業単位: **1 セッションで 1〜3 件**(同じスクリプトの件はまとめてよい)。着手前に `docs/BACKLOG.md` の BL-24 を「作業中」にする。
- 読むもの: `tools/scenario-src/README.md` → 対象のスクリプト 1 本(`grep -n 'id: "<id>"'` で該当 `build({...})` の範囲だけ)。JSON は読まない。
- 直し方: スクリプトの座標表(1 行 = 1 選手、5 列 = Step 1〜5)と `ball(...)` を直し、`npm run scenarios` で作り直す。
- 確認(この順):
  1. `node scripts/review-geometry.mjs <id>` — そのシナリオの全ステップを展開して、修正後の座標・警告を見る(`!!` が消えているか)。
  2. `npm run validate 2>&1 | grep -B1 -A3 '<id>'` — 速さ・オフサイド・重なりの警告が増えていないか。速さの警告が出たら、動きを前のステップに分散する。
  3. `npm run scenarios:check`。
- **2-3-2 版(`w7-formation-232.mjs`)は元の 3-3-1 の JSON から座標を読む**ので、元スクリプトを直せば `counter-press-232`・`press-and-cover-232`・`restart-shape-232` も直る(`rows` で相手の座標を上書きしていないことだけ確認)。
- 修正案の座標は「この条件を満たす一例」。見た目が不自然なら、各項目の **満たすべき条件** を守る範囲で変えてよい。
- 文章(`text`・`coachNote`・`coachCue`)を変えた件は `docs/SCENARIO_CATALOG.md` の該当節も合わせる(`grep -n '^####'` で行を特定)。
- 終わったら各項目の「状態」欄を更新し、BL-24 の状態にも件数を書く。

## 2. 判定基準(review-geometry.mjs の警告の意味)

| 観点 | 基準 | 理由 |
|---|---|---|
| パス経路 | 味方のパスの線分から **1.5m 以内**に相手がいる(キック時・到達時のどちらかの座標で) | 4 年生のゴロのパスは、1.5m 以内の相手に足を出されると止まる。お手本が「相手の横を通した」と言うなら、画面でもそう見えること |
| 三角形 | `triangle` オーバーレイの最小角が **25° 未満** | 一直線=サポートの角度がない。受け手が 2 人の味方の間に入ると、もう 1 本のコースも消す |
| レーン | `passLane` の open に相手が 1.5m 以内/blocked なのに 1.5m 以内にだれもいない | 画面の線と実際の配置が食いちがう |
| シュートコース | 味方の `shotCone` の中に相手がいる/相手の `shotCone` を「ふさぐ」と言う味方がコースの外にいる | 三角形は画面に赤く出るので、ずれがそのまま見える |
| 「フリー」 | 文章で「フリー・空いている」と言う味方の 3m 以内に相手(GK 除く) | 言葉と絵の一致 |
| セオリー(目視) | 1 人で 2 人を守る時のカバーの位置、ゴール側に立つ、追う相手の向き、など | 機械では取れない。4 章の「目視で確かめた観点」 |

警告は材料であって、全部を 0 にする必要はない(例: 奪った直後に、取られた相手の脇をパスが通るのは 1.3m でも自然)。
