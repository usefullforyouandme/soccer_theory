# シナリオ生成プロンプト(LLM 向け)

新しいシナリオを作るときは、下のプロンプトの【テーマ】欄を埋め、`schema/scenario.schema.json` の全文と `scenarios/side-attack-box-entry.json`(お手本)を添付して LLM に渡す。
出力は `scenarios/<id>.json` に保存し、`npm run validate` で検証する(詳細は `docs/SPEC.md` 10 章)。

---

```markdown
# 役割
あなたはジュニアサッカーの指導経験が豊富なコーチであり、サッカーのトラッキングデータ設計の専門家です。

# 目的
小学4年生向け8人制サッカー戦術学習アプリに投入する「戦術アニメーション用シナリオデータ(JSON)」を作成してください。
単なる1プレーの動きではなく、「なぜその動きが必要なのか」を子どもが実感できるよう、**1〜2プレー先の具体的な結末(成功体験・失敗によるピンチ)**までを5つのステップで設計してください。

# 出力ルール(厳守)
- 添付の JSON Schema に**厳密に従った JSON のみ**を出力する(前置き・説明文・コードフェンス以外の文字は出さない)。
- 添付のお手本 JSON と同じ構造・粒度で作る。
- 座標は小数1桁まで。`id` は kebab-case の英語にする(例: `<group>-<パターン>` → `counter-press-wing`)。
- `category`・`group`・`title` は、同じテーマの既存シナリオとそろえる。`pattern` にはボールの位置・守備の状況の違いを 16 字以内で書く(例:「サイドで取られた時」)。同じテーマの別パターンとは、初期配置と、それに合った正しい動き方が違うように作る。

# ピッチ座標系
- X軸: 0(左タッチライン)〜50(右タッチライン)、中央は25。
- Y軸: 0(相手ゴールライン)〜68(自陣ゴールライン)、ハーフウェーラインは34。
- 味方(home, ID 接頭辞 h)は Y=68 側から Y=0 側へ攻撃し、相手(away, ID 接頭辞 a)はその逆向きに攻撃する。
- 自陣PA: X 13〜37, Y 56〜68 / 相手PA: X 13〜37, Y 0〜12 / ゴール: X 22.5〜27.5。
- オフサイドルールを守る(相手陣内で、パスが出た瞬間に受け手が後ろから2人目の守備者より前にいない)。

# チーム
- 両チームとも 8人、フォーメーション 3-3-1(2-3-2 版を作る時は、味方を GK=1, DF=2・3, MF=7・6・8, FW=9・10 にする)。
- 選手ID: GK=1, LB=2, CB=4, RB=3, LM=7, CM=6, RM=8, FW=9(例: 味方7番=h7、相手9番=a9)。
- 相手は下向きに攻めるため、相手の左サイド(a2, a7)は画面の右側(X が大きい側)にいる。
- 相手チームの守備: 【例: ボール保持者にはプレスをかけ、他は中央を固める標準的な守備】

# 学習設計(厳守)
- `question`: Step 1 のあとに子どもに予想させる問いかけ(例:「{h9}と{h8}は、どこへ走ればチャンスになるかな?」)。
- `keyPoint`: 最後に出す「今日のポイント」。原則を具体的な行動で1文にする(例:「ボールに近づきすぎず、ゴール前に2人で入ろう!」)。
- `questionTitle`・`keyword`・`courseOrder`・`ruleNote`・`drills` はテーマ単位の値なので、既存テーマのパターンを作る時は同じテーマのシナリオと同じ値にする(新しいテーマは `tools/scenario-src/groups.mjs` に追加する)。`questionTitle` は答えを書かない疑問形(例:「取られた!近くの人は?」)。
- 予想を選ばせたい場面は `choices`(2〜3 択、正解は1つ。`text` 24字以内、`feedback` 40字以内)を付ける。不正解の `feedback` は、その動きをするとどうなるかを書く(責めない)。
- つづきの場面があれば `next`(`{ "id": "<シナリオ>", "label": "取られた後を見る" }`)を付ける。
- **bad で変える誤りは1つだけ**にする。誤りに関係しない味方は good と同じ考え方で動かす(何が悪かったかを子どもが特定できるように)。
- ミスは「止まっている・見ているだけ」ばかりにしない。4年生に多い「ボールへ寄ってしまう」「自分のゴールの方へ下がってしまう」「逆の方向へ動く」ミスも使う。
- 結末を「キーパーと1対1」ばかりにしない(フリーでシュート・コーナーをあたえる・はね返りを拾われる など、ミスとの因果が近いものを選ぶ)。お手本も、いつもゴールにせず「外れたけど、フリーで打てた」などの結末を混ぜる。
- ヘディングの場面と、後ろからのタックルは描かない(はね返すのは胸・足。取るのは横から・前から)。
- 誤った動きの矢印には `"judgement": "bad"` を付け、`callout`(吹き出し、8字以内)で「近づきすぎ」「見てるだけ」のようにその場で示す。良い動きにも必要に応じて good の callout を付ける。
- 因果の起点になる相手の動き(例: DF が FW について行く)にも `arrow` を付ける。
- 説明文で触れない補助線(passLane など)は描かない。
- 結末: お手本は `outcomeTone: "chance"`。ミスは失点の危機なら `"pinch"`、チャンスを逃す・相手ボールになるだけなら `"miss"`(△ 残念…)にする。無理にピンチを作らない。
- クロスや大きなキックを相手がカット・キャッチする場合は、そのステップの `ball` に `"lofted": true` を付ける(`steal` のときだけ。浮き球として描かれる)。パスの距離は 4 年生のキック力に合わせ、ゴロ・浮き球とも 20m 以内(ゴロは 10m/s 以下)、キーパーのスローは 15m 以内を目安にする。
- オフサイドを見せる場合は、そのパスのステップの `ball` に `"offside": true` を付け、`{ "type": "offsideLine", "defending": "away" }` でオフサイドラインを表示する。オフサイドかどうかは**パスが出た瞬間(前ステップの終わり)の位置**で決まる。明示しないオフサイドは不可。
- 「周りを見る」ことを見せる場合は `{ "type": "look", "player": "h6", "at": "a8" }` で見た方向を扇形で描く(`at` は選手 ID・`"ball"`・座標)。ボールだけを見ているミスは `{ "type": "look", "player": "h6", "at": "ball", "judgement": "bad" }`。
- シュートコースを見せる場合は `{ "type": "shotCone", "from": "ball", "goal": "home", "centerLine": true }` のように描く(キーパーの立ち位置の説明などに使う)。

# ステップ構成(全5ステップ、good / bad とも同じ phase 構成)
- Step 1 initial: 局面が始まる瞬間(good と bad で同じ座標)。
- Step 2 movement: ボール保持者の状況に対し、オフ・ザ・ボールの選手が動く(bad はミスして動かない/寄りすぎる)。
- Step 3 firstPlay: 最初のパスまたはドリブル。
- Step 4 nextPlay: good は良いサポートから次のパスコースやスペースが生まれ、2人目・3人目が連動する。bad はパスが詰まる、インターセプトされる、1発でかわされる。
- Step 5 outcome: good はDFライン突破・逆サイドへの展開・シュートチャンス・カウンター成功など。bad はショートカウンターでGKと1対1、ガラ空きの中央からシュートなど明確なピンチ。

# リアリティの制約
- 選手同士は 2.5m 以上離す(描画上の丸が重なって背番号が読めなくなるため)。
- `players` は各ステップ終了時点の**全16人**の座標。ボールに直接関わらない選手も、ラインの押し上げ・絞る動き・遅れて追いかける動きなどで**毎ステップ少しずつ動かす**。
- 移動速度は `durationMs` から計算して、選手は 6m/s 以下(小学生の全力疾走程度)、ボールは 25m/s 以下にする。
- ボールを持っている選手とボールの距離は 2m 以内。
- `motion` と持ち主の変化を一致させる(hold/dribble は持ち主が変わらない、ground/air はパス成功、steal は相手が奪う、shot は owner=null)。
- `arrow` の `from`/`to` は原則省略する(選手・ボールの実際の動きから自動で描かれる)。

# 文章(小学4年生向け。`targetGrade` は "middle")
- `title`(12字以内)、`explanation`・`question`・`keyPoint`(表示40字以内)、`outcomeBanner`(16字以内)、callout・space のラベルは、**小学4年生までに習う漢字(学年別漢字配当表 1〜4年)だけ**を使って書く。それ以外の漢字はひらがなにする(例:「かこまれる」「ななめ」「よる」)。
- 「GK」は使わず「キーパー」と書く。サッカー用語は使ってよいが、**お手本・ミスのそれぞれで、初めて出る説明文(question・explanation・keyPoint)に下の言いかえを添える**。`outcomeBanner` には用語を使わない(例:「カウンターでピンチ!」→「すぐにせめ返された!」)。
  | 用語 | 言いかえ(例) |
  |---|---|
  | ニア / ファー | ゴールに近い方(ニア) / 遠い方(ファー) |
  | マイナス | 後ろへもどすパス(マイナス) |
  | カウンター | すぐにせめ返された(カウンター) |
  | フリー | だれもいない所(フリー) |
  | カット | とちゅうで取った(カット) |
  | こぼれ球 | はね返ったボール(こぼれ球) |
  | スルーパス | 守りの間・後ろを通すパス(スルーパス) |
  | しぼる | 中へよる(しぼる) |
  | クロス | 横からゴール前へ上げる(クロス) |
  | カバー | 後ろで助ける(カバー) |
  | プレス | 取りに来た相手(プレス) |
- 選手名は `{h9}`(味方9番)、`{a6}`(相手6番)のトークンで書く。画面では色付きの「9番」になる。相手の選手は「相手の{a6}」のように書く。
- 分かち書きのスペースは入れない(例:「{h7}が左サイドでボールを持った。」)。
- 「だれが」「どうした」「だから どうなった」が1〜2文で分かるようにする。抽象的なまとめ(「チャンスが ふえる」)ではなく、具体的な行動や事実で書く。
- 指導者向けの説明は `theme` と `coachNote` に漢字を使って書く。
- 同じ場面を反対側(せめる側/守る側)から見たシナリオがあれば、`counterpart`(`{ "id": "<相手のシナリオ>", "label": "守る側から見る" }`)を付け、相手のシナリオにもこのシナリオへの `counterpart` を付ける。
- 指導者向けに `coachCue`(ピッチで子どもに掛ける短い言葉、40 字以内。**やることを肯定形で**。×「飛びこむな!」→ ◎「下がりながら、2人の間に立て!」)と、`drills`(このシナリオの動きを身につける練習を 1〜2 件。`title`・`players`(人数)・`area`(広さ・準備)・`rule`(ルール)・`success`(成功の目安)、必要なら `note`)も作る。
```
