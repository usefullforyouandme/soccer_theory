# 練習メニューの説明(設計)

試合の場面(シナリオ)とは別に、コーンドリブルや 2 人のパス練習の「やり方」を、今のビューアで動きとして見せる。2026-11-18 に利用者と決めた内容。

## 1. 決めたこと

| 項目 | 決定 |
|---|---|
| 主な利用者 | **指導者が練習の前に子どもに見せて説明する**。子どもが一人で見て学ぶことは主な目的にしない |
| 学習の流れ | 試合のシナリオと同じく「問いかけ → ◎ おてほん → × よくあるミス → 今日のポイント」。比べるのは判断ではなく**技術のやり方**。ミス側で変えてよい誤りは 1 つだけ(1 シナリオ 1 論点) |
| 最初のメニュー | 2 章の 8 本(コーンドリブル 4 本・2 人のパス 4 本) |
| 足の使い方 | **説明欄に「あしもと」のアップ図**を出す(足の形・ボールの当たる面を色でぬる・軸足の向き)。ピッチの上には軸足の足あとだけを置き、ピッチを見にくくしない |
| 指導者向けの情報 | 練習のページでは**最初から開いて表示**する(準備・やり方・回数・声かけ・レベルアップ・安全)。試合のシナリオは今と同じく折りたたみのまま |
| 子どもに見せる文 | 今と同じ 4 年生向けの文章ルール(4 年生までの漢字、40 字以内、肯定形の声かけ)。指導メモだけは大人向け |

前提(変えない): 写真・動画は使わず SVG だけで描く(SPEC 2 章のプライバシー方針)。右足でける場合を基本にして、指導メモに「左足でも同じ」と書く。練習は「おすすめの順番」には入れず、一覧の別の並びにする。

## 3. データとビューアの変更(BL-27)

| 今の前提 | 練習での扱い |
|---|---|
| 全 16 人を毎ステップ置く | `kind: "drill"` のときは、出てくる選手(1〜2 人+コーチ・鬼)だけでよい |
| フルピッチ 50×68 m | `area`(幅・奥行き m)を持たせ、その範囲を拡大して描く。ゴール・ライン・オフサイド・攻める方向は描かない |
| 選手とボールだけ | オーバーレイに `cone`(コーン)と `gate`(コーン 2 本の門)を追加する |
| 結末はチャンス/ピンチ | good は `chance`(◎ できた!)、bad は `miss`(△ 残念…)に固定。`pinch` は使わない |
| 足の使い方は見えない | ステップに任意の `foot`(けり足・当てる面 `inside` / `outside` / `sole` / `instep` / `toe`・軸足の向き)を持たせ、説明欄に「あしもと」図を出す。ピッチには軸足の足あとマーク。タッチの回数はボールの点で残す |
| 指導メモは折りたたみ | drill は「準備(人数・広さ・コーンの数)・やり方・回数・声かけ・レベルアップ・安全」のカードを開いて表示 |

- 一覧: 4 つ目の並び「練習から選ぶ」(ドリブル/パスの 2 区分)。
- 練習 → 試合: 「▶ 試合ではこの場面」ボタン(`next` と同じ形のリンク `match`)。
- 試合 → 練習: 今の文字だけの `drills` に、練習の id を書けるようにして「動きで見る」ボタンを出す。
- スキーマ変更なので、`schema/scenario.schema.json`・`src/types.ts`・`docs/scenario-prompt.md`・`scripts/validate.mjs` を同じセッションで合わせて直す。
- 作成は座標表スクリプト方式(`tools/scenario-src/p-*.mjs` など)。`lib.mjs` に小さいエリア用の書き方を足す。

## 4. 進め方

1. **BL-27(ビューア・スキーマ)**: 3 章の変更と、お手本として D1 を 1 本だけ作って見た目を確かめる。
2. **BL-28(練習の中身・ドリブル編)**: D2〜D4。
3. **BL-29(練習の中身・パス編)**: P1〜P4。
4. 指導者目線のレビューは、作成とは別のセッションで行う。
