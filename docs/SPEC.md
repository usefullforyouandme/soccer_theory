# 仕様書:サッカー戦術学習ツール(soccer_theory)

最終更新: 2026-11-15 / ステータス: v1.0(「見た方向」の表示と第 5 弾を追加、23 テーマ・計 50 本)

## 1. 目的
小学4年生が、8人制サッカーの試合における「セオリーの動き方」を、ブラウザ上のアニメーションで学べるようにする。
単発の動きではなく、**1〜2プレー先の結末(成功体験/失敗によるピンチ)まで見せる**ことで、「なぜその動きが必要なのか」を実感させる。

## 2. 前提・制約

| 項目 | 決定事項 |
|---|---|
| 対象 | 小学4年生(`targetGrade: "middle"`)。保護者・指導者が一緒に見ることも想定 |
| 端末 | PC、タブレット(iPad 等)。タッチ操作に対応 |
| 公開範囲 | Public(誰でも閲覧可) |
| ホスティング | GitHub Pages(静的サイト) |
| 競技形式 | 8人制(ピッチ 50m × 68m) |
| フォーメーション | 3-3-1(味方・相手とも同じ) |

### セキュリティ・プライバシー方針(子ども向けのため厳守)
- 個人情報は**一切収集しない**(ログイン、入力フォーム、アクセス解析、広告は入れない)。
- 外部へ通信しない。フォントやライブラリも同梱して、サードパーティへのリクエストを発生させない。
- 実行時に AI や API を呼ばない。シナリオは作成時に用意した JSON を再生するだけにする。
- 「JFA 公認」「JFA 監修」と受け取れる表記はしない。

## 5. 学習設計(教育方針)

子どもが「見て終わり」にならず、動きの理由を自分の言葉で言えるようになることを目標にする。

### 学習の流れ(1 シナリオ = 1 回の授業の最小単位)
| 段階 | 画面での表現 | データ |
|---|---|---|
| ① 状況をつかむ | Step 1(はじまり)を表示 | `steps[0]` |
| ② 予想する | 「考えてみよう」カードで問いかけ、「答えを見る」を押すまで進まない。答え(テーマ名)は隠し、疑問形のタイトルを出す。選択式の予想があるシナリオは、選んでから答えを見る | `question`・`questionTitle`・`choices` |
| ③ 正しい動きを見る | ◎ お手本 の Step 2〜5 | `variants.good` |
| ④ ミスと比べる | × よくあるミス、または「ならべてくらべる」(お手本の位置を薄い丸で重ねる) | `variants.bad` |
| ⑤ まとめる | 最後に「今日のポイント」を表示・読み上げ。選んだ予想への一言と、「つづき」のシナリオへのボタンも出す | `keyPoint`・`choices[].feedback`・`next` |

### シナリオ設計の原則
- **1 シナリオ 1 論点**:bad で変えてよい誤りは 1 つだけ(例:「9番と8番がゴール前に入らない」)。他の選手は good と同じ考え方で動かし、何が悪かったかを特定できるようにする。
- **因果を見せる**:原因となる相手の動き(例:DF が FW について行く)にも矢印を付け、「だからここが空く」の流れを画面で追えるようにする。
- **誤りはその場で示す**:誤った動きは赤い矢印+×(`arrow.judgement: "bad"`)と吹き出し(`callout`)で、起きた瞬間に示す。結末まで待たせない。
- **文章と画面を結びつける**:説明文の選手名は `{h9}` トークンで書く。画面ではピッチの丸と同じ色の「9番」チップになり、その選手が黄色いリングで強調される。
- **描くのは説明に関係するものだけ**:説明文で触れない補助線は描かない(注意が散るため)。
- **読みやすさ**:文章は 4 年生までに習う漢字だけを使い、表示 40 字以内を目安にする。サッカー用語(ニア、フリー、カウンターなど)は使ってよいが、お手本・ミスのどちらから見ても、**初めて出る説明文で言いかえを添える**(例:「ゴールに近い方(ニア)」。言いかえの一覧は `docs/scenario-prompt.md`)。結末の見出しには用語を使わない。用語はタップすると説明が出る。読み上げ機能(端末内の音声合成)も用意する。
- **答えを先に見せない**:テーマ名(`title`)は答えになっていることが多いので、一覧と問いかけ中は疑問形の `questionTitle` を出し、テーマ名は「答えを見る」の後に出す。一覧のサムネイルは「はじまり」の配置にする。
- **ミスの形を偏らせない**:「止まっている・見ているだけ」だけでなく、4 年生に多い「ボールへ寄ってしまう」「逆の方向へ動く」ミスも描く(検証の集計で偏りを確認する)。結末も「キーパーと 1 対 1」ばかりにせず、お手本でも「外れたけど打てた」など判断をほめる結末を混ぜる。
- **4 年生の体で再現できること**:味方のパスはゴロ・浮き球とも 20m 以内・ゴロ 10m/s 以下、キーパーのスローは 15m 以内、走る速さは 6m/s 以下を目安にする(検証で警告)。後ろからのタックル、**ヘディングの場面は描かない**(育成年代のヘディングのガイドラインに合わせる。コーナーのはね返しは胸・足で)。
- **声かけは肯定形**:`coachCue` は「〜するな」ではなく、やることを短く言う(検証で警告)。
- **形がちがっても原則は同じ**:基本は 3-3-1 で描き、主要なテーマには 2-3-2 版も用意する。指導メモに「ほかの形でも考え方は同じ」と表示する。

## 6. シナリオデータ

- 形式: `scenarios/<id>.json`、スキーマは `schema/scenario.schema.json`(JSON Schema 2020-12、`schemaVersion: 2`)。
- **テーマとパターン**:同じ原則(テーマ)でも、ボールの位置や守備の状況で動き方が変わるため、1 テーマを複数のパターンに分けて作る(詳細は `docs/SCENARIO_CATALOG.md` 2 章)。
  - `category`:種類(`build` ボールを前へ運ぶ / `attack` ゴールをねらう / `defend` ボールを取る・守る / `transition` 切りかえ / `restart` リスタート・キーパー)
  - `group`:テーマの ID。同じテーマのパターンは同じ `group`・`title`・`category` にする(検証でチェック)
  - `pattern`:パターン名(16 字以内。例:「サイドで取られた時」)
  - `questionTitle`:子ども向けの疑問形タイトル(20 字以内。答えを書かない。例:「取られた!近くの人は?」)
  - `keyword`:ずかん全体の合言葉(`look` 見る / `move` 動いて受ける / `goal` ゴールへ向かう / `switch` すぐ切りかえる / `protect` ゴールを守る)
  - `courseOrder`:おすすめの順番(テーマごとに 1 つの番号。U-10 の指導順)
  - `questionTitle`・`keyword`・`courseOrder`・`ruleNote`・`drills` はテーマ単位の値なので、`tools/scenario-src/groups.mjs` で一元管理する(同じテーマで値がずれていないかを検証でチェック)
  - `choices`(任意):選択式の予想(2〜3 択。`text`・`correct`・`feedback`。正解はちょうど 1 つ)
  - `ruleNote`(任意):ルールが大会で違う場面の注記(子ども向け。問いかけの下に小さく出す)
  - `next`(任意):つづきの場面のシナリオ(`{ "id", "label" }`。結末の後にボタンで出す)
  - `teams.home.formation`:基本は `3-3-1`。2-3-2 版は DF 2 人(2・3)、MF 3 人(7・6・8)、FW 2 人(9・10)
  - `counterpart`(任意):同じ場面を反対側(せめる側/守る側、取った側/取られた側)から見たシナリオ。`{ "id": "<相手のシナリオ>", "label": "守る側から見る" }`。相手のシナリオからも、このシナリオを指す(おたがいに指し合う。存在・相互参照・別テーマであることを検証でチェック)
- シナリオ全体に `question`(Step 1 のあとの問いかけ)と `keyPoint`(まとめ)を持つ。
- 1 シナリオに「◎ おてほん(good)」と「× よくあるミス(bad)」の 2 パターンを持つ。どちらも 5 ステップで構成する。

| Step | phase | 内容 |
|---|---|---|
| 1 | initial | 初期配置(good と bad で原則同じ) |
| 2 | movement | オフ・ザ・ボールの動き出し(bad は動かない/寄りすぎる) |
| 3 | firstPlay | 1 プレー目(パス or ドリブル) |
| 4 | nextPlay | 1 プレー先(good: 連動して次のコースが生まれる/bad: 詰まる・奪われる) |
| 5 | outcome | 2 プレー先の結末(good: チャンス/bad: 失点のピンチ、または「残念」=チャンスを逃した・相手ボールになった)+ `outcomeBanner` |

### 各ステップのデータ
- `players`: **ステップ終了時点**の全 16 人の座標。ボールに関わらない選手も毎回少しずつ動かす。
- `ball`: 座標、持ち主 `owner`、そこへの動き方 `motion`。
  - `motion` の値: `hold` / `dribble` / `ground` / `air` / `steal` / `shot`
  - `lofted`(任意、`steal` のときだけ): クロスや大きなキックなど、浮き球をカットした・キャッチした。`air` と同じくボールを浮かせて描く
- `durationMs`: 前ステップからこのステップへ移る実時間。1 倍速再生の長さになる(比較表示では good/bad の長い方に合わせる)。
- `explanation`: `{h7}` のような選手トークンを含められる。画面では色付きの「7番」になる(`targetGrade: "low"` のときは「7ばん」)。
- `focus`(任意): 黄色いリングで強調する選手。省略時は `explanation` に出てくる選手。
- `overlays`: 図示用のオーバーレイ。
  - `arrow`: 走る・ドリブル・パス・シュートの矢印。`from`/`to` を省略すると、選手(またはボール)の前ステップ位置 → 現ステップ位置から自動で描く(矢印と実際の動きが食い違わない)。`judgement: "bad"` で誤った動きとして赤く描く。
  - `callout`: 選手の頭上の吹き出し(8 字以内、`tone: good | bad`)
  - `offsideLine`: オフサイドライン(`defending` = 守っているチーム)。守備側の後ろから 2 人目とボールのうち守備側のゴールに近い方に横線を引き、選手の動きに追従する。攻撃側の自陣(ハーフウェーラインより手前)には来ない。パスのステップでは「パスが出た瞬間」(前ステップの終わり)の位置で止めて表示する(オフサイドの判定基準を見せるため)。
  - `look`: 選手が見た方向(視野)の扇形。`player` と `at`(見る先: 選手 ID、`"ball"`、または座標)を指定する。`judgement: "good"`(省略時)は黄色の広い扇形=周りを見ている、`"bad"` は赤いせまい扇形=ボールだけを見ている。そのステップの間は、選手の向き(三角)も見る先へ向く。凡例の「見た方向」は、`look` を使うシナリオだけに出す。
  - `shotCone`: シュートコース。`from`(選手 ID または `"ball"`)と `goal`(ねらうゴール)の両ポストを結ぶ三角形。`centerLine: true` で真ん中の線(キーパーが立つ目安)を描く。ゴールに近い所では三角形が小さくなり選手の丸に隠れるため、選手より手前に半透明で描く。
- `ball.offside`(任意): このパスがオフサイドであることを明示する(ミス側でオフサイドを結末として見せる場合)。受けた瞬間に「× オフサイド!」の吹き出しを出す。
- `variants.*.outcomeTone`(任意): 結末の種類。`chance`(◎ チャンス!緑)/ `pinch`(× ピンチ!赤)/ `miss`(△ 残念…灰)。省略時は good = chance、bad = pinch。ミス側でも、失点の危機ではなく「チャンスを逃す」「相手ボールになる」結末は `miss` にする(無理にピンチを作らない)。
  - `passLane`: パスコース(`open` / `blocked`)
  - `space`: 注目させたいスペースの楕円(ラベル付き)
  - `triangle`: 3 人で作るトライアングル
  - `passLane` と `triangle` は選手 ID で指定するので、選手が動くと一緒に動く。

### 文章ルール(小学4年生向け)
- 表示文字数の目安は、`explanation`・`question`・`keyPoint` が 40 字以内、`title` が 12 字以内、`outcomeBanner` が 16 字以内。
- 漢字は学年別漢字配当表の 1〜4 年生分(642 字)だけを使う。それ以外はひらがなで書く(例:「かこまれる」「ななめ」)。分かち書きのスペースは入れない。
- 「GK」は使わず「キーパー」と書く。サッカー用語は、初めて出るときに言いかえを添える。
- 結論は抽象的にせず、具体的な行動で書く(×「チャンスがふえる」→ ◎「ゴール前に2人で入ろう」)。
- 対象学年を変える場合は `targetGrade` を `low`(ひらがな・カタカナのみ、30 字以内)にする。
- 指導者向けの説明は、`theme` と `coachNote` に書く(漢字を使ってよい)。練習につなげる情報として、`coachCue`(ピッチで子どもに掛ける短い言葉、40 字以内。肯定形)と `drills`(関連する練習、最大 3 件。`title`・`players`(人数)・`area`(広さ)・`rule`(ルール)・`success`(成功の目安)・`note`(任意))も書ける。

## 7. 検証(`npm run validate`)
LLM で作ったデータにはミスが混ざる前提で、コミット前と CI で必ず検証する。

| 種別 | チェック内容 |
|---|---|
| スキーマ | 型、必須項目、座標範囲(X 0〜50 / Y 0〜68)、文字数、5 ステップ |
| エラー | phase の順序、全選手がそろっているか、ボールと持ち主の距離 ≤ 2m、移動速度(選手 > 8m/s、ボール > 25m/s)、motion と持ち主の変化が合っているか、**オフサイド**(パスが出た瞬間=前ステップ終了時の位置で判定。`ball.offside: true` を明示したパスだけ許可し、明示があるのにオフサイドでなければエラー)、オーバーレイ・選手トークンの参照先、id とファイル名の一致 |
| 警告(4 年生向けの基準) | 味方・相手のパス > 20m、ゴロのパス > 10m/s(キーパーのキック・スロー、コーナー・スローインは除く)、用語(ニア・フリー・カット・カウンターなど)が初めて出る説明文に言いかえがない、結末の見出しに用語がある、`coachCue` が否定形、`questionTitle`・`keyword`・`courseOrder` がない |
| まとめ表示 | ミスが「動かない」型の本数、ミスの結末が「キーパーと 1 対 1」の本数、お手本がゴールで終わる本数(偏りの確認用) |
| テーマ単位 | 同じテーマで `title`・`category`・`questionTitle`・`keyword`・`courseOrder`・`ruleNote` が同じか、`courseOrder` がテーマ間で重なっていないか、`counterpart`・`next` の参照先があるか |
| 警告 | 選手の移動速度 > 6m/s、前ステップから全く動いていない選手、選手同士の重なり(< 2.5m)、**good と bad の Step 1 の不一致**、**矢印と実際の動きのずれ**(> 1.5m)、子どもに見えるすべての文字列の漢字(`middle` は 4 年生までに習わない漢字、`low` は漢字すべて)、表示文字数の超過(`middle` 40 字 / `low` 30 字) |

## 8. 画面仕様(ビューア)

- **シナリオ一覧**(`#/`):「おすすめの順番」(既定。`courseOrder` 順に 3 つのステップに分ける)と「種類ごと」(種類 → テーマ → パターン)を切りかえられる(選んだ方は端末に記憶)。テーマの見出しは疑問形の `questionTitle` と合言葉のチップ(色と文字で区別)、パターンごとにカード(「はじまり」のサムネイル+パターン名)を表示する。指導者向けの `theme` は一覧に出さない。同じテーマの中では 3-3-1 のパターンを先に、2-3-2 版を後ろに並べる。
- **パターンの切りかえ**:再生画面の見出しにパターン名を表示し、「パターン」ボタンで同じテーマの別パターンへ移動できる。
- **反対側から見る**:`counterpart` があるシナリオでは、見出しに「⇄ 守る側から見る」などのボタン(相手シナリオのタイトルとパターン名つき)を出し、反対側のシナリオへ移動できる。今ある組み合わせ: 2対1の攻め ↔ 2対1の守り(2 組)、味方のコーナーキック ↔ コーナーキックの守り方(2 組)、サイドからゴール前へ(左)↔ ゴール前の守り(クロス)、相手の後ろへ走る(中央)↔ ゴール前の守り(スルーパス)、取られたらすぐ取り返す(中央)↔ 取ったら前を見よう(中央)。
- **再生画面**(`#/s/<id>`):ハッシュ方式のルーティングにして、GitHub Pages のサブパスでもそのまま動くようにする。
- **再生画面**:
  - ピッチ(SVG)。選手は丸の中に背番号を表示し、味方は青、相手は赤にする。
  - 「◎ おてほん / × よくあるミス」の切り替え。並べて同時に再生するモードもある。切り替えた時は再生を止め、必ず「1. はじまり」(問いかけ)の状態に戻す(途中のステップのまま切り替わると、流れが分からなくなるため)。
  - 「⏮ 最初から / ◀ もどる / ▶ スタート・⏸ 止める / ▶ 次へ」、速度の切り替え(🐇 ふつう 1 倍 / 🐢 ゆっくり 0.5 倍 / 🐌 もっとゆっくり 0.25 倍)、🔊 読み上げ(Web Speech API。端末内で完結)。
  - Step 1 では「考えてみよう」カード(`question`)を出し、操作ボタンの「▶ 答えを見る」を押すと再生が始まる。再生中もカードは消さず、問いかけを薄く残す(問いを見ながら答えを確かめる)。問いかけ中は見出しにテーマ名ではなく「? 疑問形のタイトル」を出し、答えを見た後にテーマ名へ切りかえる。`ruleNote` があれば問いかけの下に小さく出す。
  - `choices` があるシナリオでは、問いかけの下に A〜C の選択肢を出し、選ぶまで「答えを見る」を押せない。最後に、選んだ予想への一言(◎ 正かい / △ えらんだ人へ)を出す。
  - 最後は「今日のポイント」カード(`keyPoint`)を出す。`next` があれば「▶ つづき」のボタンを出す。
  - **操作ボタンの位置を動かさない**:問いかけとポイントは同じ場所に重ねて置き、カードの高さを大きい方に固定する。ステップの説明欄も、いちばん長いステップの文の高さに固定する。選んだ予想への一言も全選択肢分を重ねて高さを取っておく。スマホ幅(480px 以下)の操作ボタンは「⏮ ◀ 再生 ▶」「速さ・読み上げ・ことば」の 2 段の固定配置にし、文言が変わっても折り返さない。
  - 説明文の用語(ニア・フリーなど)は点線の下線つきで、タップすると短い説明が出る。「📖 ことば」ボタンで、そのシナリオに出てくる用語の一覧を開ける(`src/glossary.ts`)。
  - 「保護者・指導者の方へ」欄で「ポジションを表示する」を選ぶと、ピッチの丸の下と説明文のチップに「左MF」「真ん中DF」などのポジション名を出す(相手は向きが逆で分かりにくいので DF・MF・FW だけ)。
  - 自動再生では、ステップごとに文章を読む時間(1 倍速で 2.2 秒)を取る。読み上げがオンのときは読み終わるまで待つ。
  - 「止める」は途中のコマのまま止まる。時間バー(スクラバー)をドラッグすると、任意の瞬間を表示できる。
  - キーボード:スペースで再生/停止、← → でステップを移動。
  - ステップ番号(1〜5:はじまり / 動き出し / パス・ドリブル / その後 / 結果)を押すと、そのステップへ直接移動する。
  - ステップの `title` と `explanation` は大きな文字で表示する。選手名はピッチの丸と同じ色のチップにする。
  - Step 5 で `outcomeBanner` を表示する(`outcomeTone` に応じて ◎ チャンス!緑 / × ピンチ!赤 / △ 残念…灰)。選手・ボール・ボールを持つ選手が攻めるゴールまでのコース(決着点)をなるべく隠さない高さを自動で選ぶ(同じ条件ならボールから遠い方)。
  - シュートがゴールに入った瞬間に、ネットの揺れ・波紋・紙ふぶきを出す。このときバナーは 0.6 秒遅らせて、ボールが入る瞬間を見せる。
  - 説明文に出てくる選手(または `focus`)を黄色いリングで強調し、これまでの動きを薄い足あと(点線)で残す。
  - 矢印は色と線の形の両方で区別する:走る = 白の破線(相手はピンク)/ パス = 黄色の実線(相手はオレンジ)/ ドリブル = 小さな丸の連なり / シュート = 太い黄色 / ミスの動き = 赤+×。画面の凡例にも載せる。
  - 吹き出し(◎ 緑 / × 赤)で、良い動き・悪い動きをその場で示す。
  - 選手の丸に向き(小さな三角)を付ける。動いているときは進む方向、止まっているときはボールの方向を向く。
  - ボールは半径 1m で模様付き。持っているときは、選手の丸に隠れないよう足もとの外側に描く。
  - ピッチの左の余白に「せめる方向」の矢印、上下に「相手のゴール」「自分のゴール」を描く。
  - 「ならべてくらべる」では、ミス側のピッチに、お手本と 4m 以上ずれている味方の「お手本の位置」を薄い丸で重ねる。
  - レイアウト:PC 幅(900px 以上)の 1 パターン表示では、ピッチの右に説明と操作を置く(カードは操作ボタンの上)。比較表示とタブレット縦・スマホでは、操作エリアを画面下に固定し、カードはピッチの上に置く(固定した操作エリアにカードを入れるとピッチが隠れるため)。この場合、答えを見始めた時にピッチの下端が見えるところまで画面を送る(操作エリアの固定が外れない範囲に限る)。
  - 「保護者・指導者の方へ(指導メモ)」の折りたたみ欄に、`theme`・`coachNote`・フォーメーションの注記・ポジション表示の切りかえ・`keyPoint`・`coachCue`(声かけの例)・`drills`(関連する練習。人数 / 広さ / ルール / 成功の目安)を表示する。
  - 一覧のサムネイルは Step 1(はじまり)の配置を縮小したもので、ラベルと吹き出しは描かない(動きを見せると答えが分かるため)。
- **アニメーション**:ステップ間の座標を ease-in-out で補間する。ボールは、`hold` と `dribble` のときは選手と同じ動きをする。パス・奪取・シュートのときは、少し遅れて出て減速しながら届く。`air` のときは、ボールを大きくし影をずらして浮いて見せる。
- **アクセシビリティ**:タップ領域は 44px 以上。色だけに頼らない(◎ と × の記号、線の形を併用)。動きを減らす設定(prefers-reduced-motion)を尊重する(ゴールの演出は枠の色だけにする)。説明文の aria-live は 1 か所だけにする。

## 11. シナリオ作成フロー
シナリオの作り方は 2 通りある。今ある 58 本はすべて B(座標表のスクリプト)で作っている。

**A. LLM で JSON を作る**
1. `docs/scenario-prompt.md` のテーマ欄を埋めて LLM に渡す。
2. 出力を `scenarios/<id>.json` として保存する。
3. `npm run validate` を実行し、エラーが無くなるまで修正する。警告も原則ゼロにする。
4. `npm run dev` でビューアを起動し、動きを目視確認する(指導者の目線で不自然な点がないか)。
5. コミットして main に push すると、CI で再度検証され、問題がなければ GitHub Pages に公開される。

**B. 座標表のスクリプトで作る(`tools/scenario-src/`)**
1. 選手 16 人 × 5 ステップの座標表と、文章・ボール・オーバーレイをスクリプトに書く(書き方は `tools/scenario-src/README.md`)。
2. `npm run scenarios` で `scenarios/*.json` を作り直し、`npm run validate` で検証する。
3. このスクリプトから作ったシナリオは、JSON を直接直さず、スクリプトを直して作り直す。`npm run scenarios:check`(CI でも実行)が、スクリプトと JSON のずれを検出する。
