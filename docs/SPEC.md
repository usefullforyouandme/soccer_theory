# 仕様書:サッカー戦術学習ツール(soccer_theory)

最終更新: 2026-11-15 / ステータス: ドラフト v0.1

## 1. 目的
小学生(低学年)が、8人制サッカーの試合における「セオリーの動き方」を、ブラウザ上のアニメーションで学べるようにする。
単発の動きではなく、**1〜2プレー先の結末(成功体験/失敗によるピンチ)まで見せる**ことで、「なぜその動きが必要なのか」を実感させる。

## 2. 前提・制約

| 項目 | 決定事項 |
|---|---|
| 対象 | 小学校低学年(1〜3年生)。保護者・指導者が一緒に見ることも想定 |
| 端末 | PC、タブレット(iPad 等)。タッチ操作に対応 |
| 公開範囲 | Public(誰でも閲覧可) |
| ホスティング | GitHub Pages(静的サイト) |
| 競技形式 | 8人制(ピッチ 50m × 68m) |
| フォーメーション | 3-3-1(味方・相手とも同じ) |

### セキュリティ・プライバシー方針(子ども向けのため厳守)
- 個人情報は**一切収集しない**(ログイン、入力フォーム、アクセス解析、広告は入れない)。
- 外部へ通信しない。フォントやライブラリも同梱して、サードパーティへのリクエストを発生させない。
- 実行時に AI や API を呼ばない。シナリオは作成時に用意した JSON を再生するだけにする。
- 「JFA 公認」「JFA 監修」と受け取れる表記はしない。

## 3. 座標系

| 要素 | 座標 |
|---|---|
| X 軸 | 0(左タッチライン)〜 50(右タッチライン)、中央 25 |
| Y 軸 | 0(相手ゴールライン)〜 68(自陣ゴールライン)、ハーフウェーライン 34 |
| 相手ペナルティエリア | X 13〜37 / Y 0〜12 |
| 自陣ペナルティエリア | X 13〜37 / Y 56〜68 |
| ゴール(幅 5m) | X 22.5〜27.5 |

- 味方(home)は下(Y=68 側)から上(Y=0 側)へ攻める。
- 描画は SVG の `viewBox="0 0 50 68"` で行う(座標をそのまま描画に使える)。

|---|---|---|

## 5. シナリオデータ

- 形式: `scenarios/<id>.json`、スキーマは `schema/scenario.schema.json`(JSON Schema 2020-12)。
- 1 シナリオに「◎ おてほん(good)」と「× よくあるミス(bad)」の 2 パターンを持つ。どちらも 5 ステップで構成する。

| Step | phase | 内容 |
|---|---|---|
| 1 | initial | 初期配置(good と bad で原則同じ) |
| 2 | movement | オフ・ザ・ボールの動き出し(bad は動かない/寄りすぎる) |
| 3 | firstPlay | 1 プレー目(パス or ドリブル) |
| 4 | nextPlay | 1 プレー先(good: 連動して次のコースが生まれる/bad: 詰まる・奪われる) |
| 5 | outcome | 2 プレー先の結末(good: チャンス/bad: 失点のピンチ)+ `outcomeBanner` |

### 各ステップのデータ
- `players`: **ステップ終了時点**の全 16 人の座標。ボールに関わらない選手も毎回少しずつ動かす。
- `ball`: 座標、持ち主 `owner`、そこへの動き方 `motion`。
  - `motion` の値: `hold` / `dribble` / `ground` / `air` / `steal` / `shot`
- `durationMs`: 前ステップからこのステップへ移る実時間。1 倍速再生の長さになる。
- `overlays`: 図示用のオーバーレイ。
  - `arrow`: 走る・ドリブル・パス・シュートの矢印(座標で指定)
  - `passLane`: パスコース(`open` / `blocked`)
  - `space`: 注目させたいスペースの楕円(ラベル付き)
  - `triangle`: 3 人で作るトライアングル
  - `passLane` と `triangle` は選手 ID で指定するので、選手が動くと一緒に動く。

### 文章ルール(低学年向け)
- `explanation` は 40 字以内、`title` は 12 字以内、`outcomeBanner` は 16 字以内。
- ひらがな・カタカナを中心にし、漢字は使わない。数字と「GK」は使ってよい。分かち書きのように、文節ごとに半角スペースを入れる。
- 指導者向けの説明は、`theme` と `coachNote` に書く(漢字を使ってよい)。

## 6. 検証(`npm run validate`)
LLM で作ったデータにはミスが混ざる前提で、コミット前と CI で必ず検証する。

| 種別 | チェック内容 |
|---|---|
| スキーマ | 型、必須項目、座標範囲(X 0〜50 / Y 0〜68)、文字数、5 ステップ |
| エラー | phase の順序、全選手がそろっているか、ボールと持ち主の距離 ≤ 2m、移動速度(選手 > 8m/s、ボール > 25m/s)、motion と持ち主の変化が合っているか、オーバーレイの参照先、id とファイル名の一致 |
| 警告 | 選手の移動速度 > 6m/s、前ステップから全く動いていない選手、選手同士の重なり(< 1m)、低学年向けの文章に漢字が含まれる |

## 7. 画面仕様(ビューア)※次フェーズで実装

- **シナリオ一覧**:カードを大きく表示する(タイトル+サムネイル)。
- **再生画面**:
  - ピッチ(SVG)。選手は丸の中に背番号を表示し、味方は青、相手は赤にする。
  - 「◎ おてほん / × よくあるミス」の切り替え。並べて同時に再生するモードもある。
  - 「▶ さいせい / ⏸ とめる / ◀ もどる / ▶ つぎへ」、速度の切り替え(0.5 倍 / 1 倍)。
  - ステップの `title` と `explanation` は大きな文字で表示する。
  - Step 5 で `outcomeBanner` を表示する(good は緑で「チャンス」、bad は赤で「ピンチ」の演出)。
- **アニメーション**:ステップ間の座標をイージングで補間する。パスとシュートのときは、ボールが出し手から受け手へ移動する。
- **アクセシビリティ**:タップ領域は 44px 以上。色だけに頼らない(◎ と × の記号を併用)。動きを減らす設定(prefers-reduced-motion)を尊重する。

## 8. 技術構成(案)

| 項目 | 採用 |
|---|---|
| 言語 | TypeScript |
| ビルド | Vite(静的ファイルを出力) |

## 9. ディレクトリ構成

```
soccer_theory/
├── docs/
│   ├── SPEC.md               # 本仕様書
│   └── scenario-prompt.md    # シナリオ生成用プロンプト(LLM 向け)
├── schema/scenario.schema.json
├── scenarios/*.json          # シナリオデータ
├── scripts/validate.mjs      # 検証スクリプト
└── .github/workflows/validate.yml
```

## 10. シナリオ作成フロー
1. `docs/scenario-prompt.md` のテーマ欄を埋めて LLM に渡す。
2. 出力を `scenarios/<id>.json` として保存する。
3. `npm run validate` を実行し、エラーが無くなるまで修正する。警告も原則ゼロにする。
4. ビューアで動きを目視確認する(指導者の目線で不自然な点がないか)。
5. コミット・push すると、CI で再度検証される。
